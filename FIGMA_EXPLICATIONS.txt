========================================================
MILESTONE 1 — MAQUETTES FIGMA
Explications pour la présentation au jury TP DWWM
========================================================

--------------------------------------------------------
1. POURQUOI FIGMA ?
--------------------------------------------------------
Figma est l'outil de maquettage standard dans l'industrie web.
Il permet de créer des maquettes interactives, de travailler
en équipe, et de documenter un design system réutilisable.
C'est l'outil que j'ai choisi pour répondre à la compétence C01
"Maquetter une interface utilisateur web ou web mobile".


--------------------------------------------------------
2. LE DESIGN SYSTEM — POURQUOI C'EST IMPORTANT
--------------------------------------------------------
Avant de créer les maquettes des pages, j'ai d'abord créé
un Design System sur une page dédiée dans Figma.

Le Design System contient :
- Les couleurs (8 styles de couleur nommés : color/primary,
  color/accent, color/background, etc.)
- La typographie (5 niveaux : text/h1 à text/small, police Inter)
- Les composants réutilisables : Bouton, Input, Card recette,
  Badge catégorie, Navbar (3 variantes), Footer
- Les grilles responsive : Desktop 12 colonnes, Tablette 8,
  Mobile 4

L'intérêt du Design System est la cohérence visuelle :
tous les éléments partagent les mêmes couleurs, polices
et espacements sur toutes les pages. Si je modifie un
composant (ex: la couleur du bouton), le changement se
répercute partout automatiquement.


--------------------------------------------------------
3. LES COMPOSANTS — LOGIQUE DE RÉUTILISABILITÉ
--------------------------------------------------------
Dans Figma, un composant (icône ◆) est un élément
"maître" que l'on instancie autant de fois que nécessaire.
Modifier le composant maître met à jour toutes ses instances.

C'est exactement la même logique qu'un composant React :
on crée un composant <Button /> une seule fois et on
l'utilise partout avec des props différentes.

Sur certaines pages, j'ai utilisé des copies directes
plutôt que des instances de composants pour les boutons.
C'est un point que j'aurais dû améliorer — j'aurais dû
systématiquement glisser les composants depuis le panneau
Assets. En React, j'ai bien appliqué cette logique de
réutilisabilité avec des composants JSX.


--------------------------------------------------------
4. LES 6 PAGES MAQUETTÉES
--------------------------------------------------------

PAGE 1 — Accueil
  Objectif : présenter l'application, attirer l'utilisateur.
  Sections : Hero (accroche), Catégories populaires,
  Recettes vedettes, Footer.
  Choix design : Hero pleine largeur avec overlay sombre
  pour mettre en valeur le texte.

PAGE 2 — Liste des recettes
  Objectif : permettre de parcourir et filtrer les recettes.
  Sections : barre de recherche, panneau filtres (catégorie,
  temps de préparation), grille de cards, pagination.
  Choix design : layout 2 colonnes sur desktop pour
  afficher filtres et résultats simultanément.

PAGE 3 — Fiche recette
  Objectif : afficher le détail complet d'une recette.
  Sections : image hero, titre + badge catégorie,
  description, liste ingrédients, étapes de préparation,
  note + difficulté + durée, bouton favori.
  Choix design : colonne droite avec les méta-informations
  (durée, difficulté, note) pour une lecture rapide.

PAGE 4 — Connexion / Inscription
  Objectif : authentifier l'utilisateur.
  2 formulaires : Connexion (email + mot de passe) et
  Inscription (prénom + email + mot de passe + confirmation).
  Choix design : card centrée sur fond clair, épurée,
  pour focaliser l'attention sur le formulaire.

PAGE 5 — Interface Admin
  Objectif : permettre à l'admin de gérer les recettes.
  Sections : sidebar navigation, stats (recettes/catégories/
  utilisateurs), tableau CRUD recettes avec boutons
  modifier/supprimer.
  Choix design : sidebar fixe à gauche, pattern standard
  des dashboards d'administration.

PAGE 6 — Schéma d'enchaînement
  Objectif : documenter les parcours utilisateur.
  3 parcours représentés :
  - Visiteur : Accueil → Liste → Fiche → Connexion
  - Utilisateur connecté : ... → Fiche → Favoris
  - Admin : Connexion → Dashboard → CRUD recettes
  Les losanges orange représentent les points de décision
  (ex: "Connecté ?"), les rectangles verts les pages.


--------------------------------------------------------
5. LE RESPONSIVE — 3 FORMATS
--------------------------------------------------------
Chaque page est maquettée en 3 formats :
- Desktop : 1440px (12 colonnes, marge 80px)
- Tablette : 768px (8 colonnes, marge 40px)
- Mobile : 375px (4 colonnes, marge 16px)

Adaptations responsive :
- Grille de cards : 3 colonnes → 2 → 1
- Filtres : colonne visible → bouton "Filtres ▼"
- Navbar : liens visibles → icône hamburger ☰
- Layout 2 colonnes → 1 colonne empilée


--------------------------------------------------------
6. CHARTE GRAPHIQUE — JUSTIFICATION DES CHOIX
--------------------------------------------------------
- Vert #2D6A4F : couleur primaire, évoque la nature,
  la fraîcheur, la cuisine saine. Sérieux et lisible.
- Orange #F77F00 : couleur d'accent, chaude et
  appétissante, attire l'œil sur les CTA et étoiles.
- Fond #FAFAF8 : blanc cassé, plus doux que le blanc pur,
  réduit la fatigue visuelle.
- Police Inter : moderne, lisible à toutes les tailles,
  gratuite et disponible nativement dans Figma.


--------------------------------------------------------
7. LIEN AVEC LE DÉVELOPPEMENT
--------------------------------------------------------
Ces maquettes servent de référence tout au long du
développement. Chaque page Figma correspond à un
composant React dans le projet :
- Accueil → src/pages/Home.jsx
- Liste → src/pages/RecipeList.jsx
- Fiche → src/pages/RecipeDetail.jsx
- Connexion → src/pages/Login.jsx / Register.jsx
- Admin → src/pages/Admin.jsx

Le Design System Figma se traduit en variables CSS et
en composants Bootstrap/Sass personnalisés côté code.
